# AssistantHub — security review and prioritized risk register

**Review date:** November 18, 2026. **Reviewed base:** `main` at `8cfc1fbf5b9e0a0e49cb0645451c9934a9d6bf45` (after merged PR #41). The UI spacing patch in this PR is separate from the security findings below.

**Scope:** Static inspection of React components, the JSON import and CSV export paths, client API code, Express routes, JWT/RBAC, login limiter, MySQL workflow/idempotency, local Docker configuration, deployment CI, release guard and available GitHub Actions dependency-audit output. This is **not** a penetration test, full SAST/DAST scan, live authenticated API test, or assertion that every vulnerability was found.

## Exposure matters

| Surface | Review conclusion |
| --- | --- |
| Public `https://leo0331.github.io/AssistantHub/` | **Static fictional-data demo**; no hosted Express server, real applicant records, shared Admin account or public MySQL service. Browser data is not protected business state. |
| Express + MySQL in `api/` | **Loopback-only** development environment (`API_HOST` accepts only `127.0.0.1`, `::1`, `localhost`), synthetic candidate records, and explicitly provisioned accounts. Not production-hosted or approved for real applicants. |
| Future hosted hiring API | **NO-GO** until object/tenant authorization, distributed abuse controls, secrets/TLS/DB hardening, audit/retention and identity operations are designed and tested. |

Risk ratings below describe the **potential impact in the stated exposure scenario**. A high-severity *future launch blocker* is not evidence that the current static site is vulnerable to that exploit.

## Findings, evidence, and corrective actions

| ID / priority | Area and evidence | Potential impact and trigger | Recommended remediation |
| --- | --- | --- | --- |
| **S01 — High; public API launch blocker** | **Missing object/tenant-level authorization.** `api/src/app.mjs` and `api/src/routes/applications.mjs` check whether an authenticated user is Viewer/Recruiter/Admin, but application lookup, candidate detail and audit history have no user-specific ownership filter. | If the API hosts multiple employers or real applicants, an otherwise valid user may read other users' records by known UUID, and Recruiter/Admin may change another tenant's application (BOLA/IDOR). **Currently synthetic, local-only.** | Add tenant/job ownership schema and DB-scoped authorization to **all** candidate, application, audit, and transition queries; deny cross-tenant access even for UUIDs found elsewhere; integration tests for each role and cross-tenant case. |
| **S02 — High; public API launch blocker** | **Single-process IP-only login limiter.** `api/src/auth/limiter.mjs` tracks failed attempts in a process-local `Map`; `api/src/routes/auth.mjs` uses it for login. | Restarts/multiple replicas reset or partition throttling; distributed password spraying and repeated attempts across IPs can evade effective limits. | Use shared atomic rate limiting (Redis/gateway), per-account plus IP/device constraints, sensible backoff, monitored 401/429 counts and proxy trust configuration. |
| **S03 — High; public API launch blocker** | **Dev-only deployment/secrets.** `api/src/config.mjs` prevents nonloopback binds, and `docker-compose.yml` has explicitly labeled, fixed **local-development** MySQL credentials (host port bound to loopback). `api/src/db/connection.mjs` has no explicit production DB TLS/CA or secret-manager integration. | Copying these dev defaults into an Internet-facing deployment would expose credentials/transport and operational security gaps. This is **not current public exposure**. | Retain loopback guard. For a separate production infrastructure design: network/DB isolation, TLS end-to-end and certificate validation, managed secret rotation, least-privilege DB accounts, monitored backups/restore drills and a deployment review. |
| **S04 — Medium; current offline-demo file export path** | **CSV formula injection is possible with untrusted imported demo JSON.** `src/App.jsx` converts JSON shortlist fields to strings (length-limited, but not spreadsheet-formula neutralized) and gives the resulting rows directly to `react-csv`'s `CSVLink`. | After a person imports an intentionally crafted JSON file and opens the exported CSV in spreadsheet software, a value beginning with `=`, `+`, `-`, `@`, or control/leading whitespace may be treated as a formula. **Not remote code execution in the site itself**, and severity depends on spreadsheet behavior. | Escape spreadsheet-formula prefixes in **exported CSV fields** (not the app's in-memory original values), including leading whitespace, tabs and line breaks. Add unit tests for all user-importable fields; keep CSV quoting. |
| **S05 — Medium; browser defense in depth** | **No explicit static-site CSP policy in repository `index.html`.** The API sends a restrictive CSP for JSON responses in `api/src/app.mjs`, but this does **not** protect the separate GitHub Pages React HTML. The map also fetches third-party OSM tiles (`src/ProfileCards.jsx`). | If a future XSS or compromised script occurs, a missing/weak HTML CSP provides no additional containment. API bearer tokens are in memory rather than localStorage, but in-memory tokens remain accessible to malicious same-origin script. **No exploitable XSS was established in this review.** | Design and test an HTML CSP for the static host, including required Vite script/style/font/map origins; consider a deployment service that supports HTTP security headers. Audit any future HTML injection or third-party script integration. |
| **S06 — Medium; dependency and tooling maintenance** | **Known dependency audit findings.** [Latest observed main deployment](https://github.com/LEO0331/AssistantHub/actions/runs/44254531485) reported **43 full-root affected packages** (39 high, 4 moderate) but **0 production-only root findings**. [Most recent accessible API CI audit](https://github.com/LEO0331/AssistantHub/actions/runs/44251717524) reported **6 full-API affected packages** (4 high, 2 moderate), including **2 moderate in the API production subset**. | Development/build dependencies can affect CI/supply chain; API moderate production advisories should be triaged for real exposure. Package counts are **not** exploit proofs or an exact count of distinct advisories. | Generate fresh advisory IDs and paths in `npm audit --json` for each package tree; update/transitively override only with reviewed peer-compatibility, lockfile, build and API tests. Keep high/critical production gates and report-only full audit. |
| **S07 — Medium; future public authentication** | **Token lifecycle limitations.** `api/src/auth/tokens.mjs` signs HS256 bearer JWTs valid for 15 minutes; `api/src/auth/middleware.mjs` rechecks current active accounts/roles, but there is no per-token denylist, refresh-session model, or documented key-rotation mechanism. | Individual stolen tokens remain usable until expiry unless the user account is disabled (mitigation already present); key compromise requires coordinated signing-key rotation. | Add server-side session/token revocation as needed, issuer/key rotation with staged verification, device/session audit and robust login/session monitoring before real users. |
| **S08 — Medium; data integrity and operations** | **Audit and retry retention limitations.** `api/src/services/workflowService.mjs` records application transitions and audit/idempotency atomically; `api/scripts/prune-idempotency.mjs` is manual. There are no tamper-evident append-only DB grants, remote audit sink, or documented backup restore tests. | DB-administrator compromise can alter audits; idempotency replay expires after retained keys are pruned (seven-day retention). Browser-memory retry keys disappear on reload. | Grant DB users minimal write permissions, retain tamper-evident external audit, schedule/test controlled retention and backups, preserve transaction/audit tests, define unknown-response recovery beyond retention. |
| **S09 — Low–Medium; current offline demo** | **Unbounded imported record count and localStorage persistence.** `src/App.jsx` imposes a 2 MB JSON file limit and per-field lengths but no maximum item count for `shortlist`/`inquiries`. `src/hooks/usePersistentState.js` persists shortlist/seed/source to localStorage. | A crafted large import can generate many objects and lead to sluggish rendering, memory pressure or storage quota errors. Users entering **real** personal data could leave it in browser storage on shared devices. | Bound import array counts and allowed field types, surface quota errors gracefully, add large/malicious import tests; label the site synthetic-only and discourage real PII. |
| **S10 — Low; privacy notice** | **Third-party map requests.** `src/ProfileCards.jsx` loads OpenStreetMap tiles on opening a map dialog. | Browser IP/user-agent and tile coordinates are sent to the tile provider when used. | Show a concise external-map notice if privacy matters, or host/proxy map assets under a reviewed service/consent model. |
| **S11 — Unverified; repository governance** | **Branch protection, CodeQL/code scanning, Dependabot-alert and secret-scanning settings could not be inspected with the current GitHub permissions.** The branch-protection endpoint returned HTTP 403; scanner-alert endpoints were inaccessible. GitHub Actions checks **do** use SHA-pinned actions, explicit token permissions and release/audit gates in tracked workflow files. | Required reviews/status checks and scanner coverage may be absent, but **their absence has not been established**. | Verify Settings → Branches/Rulesets, Security → Code security, Dependabot alerts, secret scanning and whether public PRs must pass CI. Require reviewer approval and CODEOWNERS for security/deployment changes. |
| **S12 — Low; reproducibility** | **Mutable MySQL image tag.** `docker-compose.yml` and CI use `mysql:8.4`, which resolves to a moving image within that line. | Rebuilds may pick up different OS/base components; image contents are not locked to a digest. | Pin container digests for reproducible CI or establish a routine controlled digest-update mechanism with DB integration tests. |

### Existing defenses worth preserving

- Public GitHub Pages is compiled **without a backend URL**; `scripts/release-guard.mjs` checks the artifact for private/server files and known sensitive markers. This is a guardrail, **not a comprehensive secret scanner**.
- API is loopback-only, with exact-origin CORS, max 4 KB JSON body, `no-store`, `nosniff`, frame restrictions, sanitized response errors and request-correlation logs.
- Passwords use salted `scrypt` and a dummy-hash path for nonexistent accounts; JWTs have issuer/audience, signature and expiry validation, and active-role DB rechecking.
- Hiring transitions use conditional MySQL version updates, transactionally inserted audit events and actor-scoped idempotent response replay.
- GitHub Actions pin actions to complete SHAs, use scoped workflow tokens and strict `npm ci`; the Pages build and API CI gate high/critical **production** dependency findings.
- Root React/React DOM remains at compatible React 18.3.1 with a preinstall peer-dependency check rather than bypassing resolution errors.

### Suggested follow-up sequence

1. **Public demo now:** harden CSV export against spreadsheet formulas, bound JSON import arrays and add negative tests. Add reviewed Pages CSP if compatible with static hosting and map dependencies.
2. **Dependencies and governance:** triage the two API moderate production findings and root dev-tool chain, update compatible packages in isolated PRs, verify branch protection and activate/inspect repository scanners.
3. **Only if publicly hosting a backend:** implement record/tenant ownership before any real candidates, distributed login/abuse controls, production secret/TLS design, token/key lifecycle, audit retention and backup/recovery evidence.
4. **Operational maturity:** schedule retention under a clear policy, monitor health/alerts, run restore drills and secure the external map/data-processing integrations.

**Conclusion:** the available evidence supports an **offline-only public portfolio demo with separate local synthetic-data backend**. It does **not** support a conclusion of zero vulnerabilities, a fully completed security audit, or readiness to expose a multi-user hiring API or real applicant information.
